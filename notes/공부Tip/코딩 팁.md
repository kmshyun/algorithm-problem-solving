# 🧭 코딩 팁

> 출처: Notion "2026 프로그래밍과 문제해결"

## 📝 문제 풀기 전 3분

1. 입력·출력 형식과 제약 조건부터 적기
2. N의 크기를 보고 쓸 수 있는 시간 복잡도 가늠하기
3. 예제 입력을 손으로 한 번 따라가보기
4. 코드는 그다음에!

## 🔁 복습하는 법

- 코드를 외우지 말고 구조를 이해하기 (재귀는 base/recursive case, 백트래킹은 선택→탐색→되돌리기)
- 빈 파일에 기본 코드를 안 보고 다시 짜보기
- 틀린 문제는 "막혔던 부분" 칸에 이유를 한 줄이라도 적기
- 이틀 뒤에 같은 문제 다시 풀어보기

## ⏱️ N의 크기로 알고리즘 고르기

파이썬은 1초에 대략 수천만 번 연산이 한계.

| N의 범위 | 가능한 시간 복잡도 | 떠올릴 알고리즘 |
|----------|-------------------|-----------------|
| N ≤ 10 | O(N!) | 순열 백트래킹 |
| N ≤ 20 | O(2ⁿ) | 부분집합 백트래킹 (넣는다/안 넣는다) |
| N ≤ 500 | O(N³) | 3중 반복문 |
| N ≤ 5,000 | O(N²) | 2중 반복문 |
| N ≤ 100,000 ~ 1,000,000 | O(N log N), O(N) | 정렬, 해싱, 누적합, 투 포인터, DFS/BFS, 다익스트라 |

## 🔎 문제 문장 → 알고리즘 신호

| 문제에 이런 말이 나오면 | 이걸 의심 | 단원 |
|------------------------|-----------|------|
| "이 값이 있나?", "몇 번 나왔나?"를 빠르게 | 해싱 (set, dict) | 2 |
| 괄호 짝, 되돌리기, 가장 최근 것부터 | 스택 | 3 |
| 구간 합을 여러 번 | 누적합 | 4 |
| 연속된 부분 배열, 길이 k인 구간 | 투 포인터, 슬라이딩 윈도우 | 4 |
| 모든 경우, 가능한 조합을 전부 | 백트래킹 | 5 |
| 연결돼 있나?, 덩어리 몇 개? | DFS / BFS | 6, 7 |
| 최소 몇 칸/번/초 (비용이 모두 같음) | BFS | 7 |
| 최소 비용, 최단 거리 (간선마다 비용 다름) | 다익스트라 | 8 |

## ✅ 제출 전 체크리스트

- [ ] 격자에서 범위 검사를 맨 앞에 두었나?
- [ ] BFS에서 방문 처리를 큐에 넣을 때 했나?
- [ ] 정점 번호가 1부터인지 0부터인지 맞췄나? (n+1 크기)
- [ ] 답이 없는 경우, 값이 1개인 경우, 최댓값이 여러 개인 경우를 넣어봤나?
