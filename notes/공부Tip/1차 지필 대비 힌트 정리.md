# 1️⃣ 해싱 — set / dict

| 도구 | 언제 | 15제 |
|------|------|------|
| `set` | 존재 여부 반복 확인 / 중복 제거·확인 | 1, 2 |
| `dict` | set 기능 + key에 대응되는 value 필요 | 3 (Counter 직접 구현) |

- `x in list`는 O(N), `x in set`은 평균 O(1). N, M = 100,000이면 list는 시간 초과.

```py
count = {}
for s in samples:
    if s in count:
        count[s] += 1
    else:
        count[s] = 1
print(count[q] if q in count else 0)   # 또는 count.get(q, 0)
```

# 2️⃣ 재귀

1. 같은 형태의 더 작은 문제로 쪼갤 수 있나?
2. Base case: 더 줄일 수 없을 때 바로 답하는 경우
3. Recursive case: 작은 문제의 답을 어떻게 합치나?
4. 재귀 호출 사이에 무엇을 전달/반환하나?

| 15제 | Base case | Recursive case |
|------|-----------|----------------|
| 4번 정수 개수 | 정수 → `return 1` | 리스트 → 원소마다 `f(item)`을 더함 |
| 5번 최대 깊이 | 정수 → 0, 빈 리스트 → 1 | 원소들 깊이 중 최댓값 + 1 |

> Base case 없으면 RecursionError(스택 오버플로).

# 3️⃣ 백트래킹

재귀 + 선택 → 탐색 → 복원. 기본형 + 코드 빈칸 + "왜?" 서술.

- 선택(Choose): state에 넣고 used 표시
- 탐색(Explore): 다음 단계 재귀, 완성 조건에서 멈춤
- 복원(Restore): pop + used = False (선택과 정확히 짝)

```py
def backtrack():
    if len(state) == M:        # 완성
        print(*state)
        return
    for i in range(1, N + 1):
        if used[i]:            # 가지치기
            continue
        state.append(i)        # Choose
        used[i] = True
        backtrack()            # Explore
        state.pop()            # Restore
        used[i] = False
```

> **복원 안 하면?** `state.pop()`을 빼면 앞에서 고른 수가 남아 길이가 M을 넘고 `1 2` 하나만 출력, 나머지 누락. `used[i]=False`를 빼면 한 번 쓴 수를 다른 가지에서 못 써서 일부 수열 누락.
>
> **7번 가지치기 3개**: ① `used[i]` ② `not state and i == F`(첫 자리 F 금지) ③ `state and state[-1] % 2 == i % 2`(앞 수와 홀짝 같음). 0개 판별 위해 `count += backtrack()`.

# 4️⃣ DFS / BFS

|  | DFS | BFS |
|--|-----|-----|
| 방식 | 깊이 먼저 | 가까운 층부터 |
| 구현 | 재귀(스택) | `deque` 큐 |
| 최단경로 | ❌ | ⭕ (가중치 없을 때 간선 수 기준) |
| visited 표시 | 함수 들어갈 때 | **큐에 넣을 때** |

- 공통: 도달하는 정점 집합은 같음 / visited 필수
- **visited 빼면?** 무방향에서 A→B→A→B 무한 왕복. DFS는 RecursionError, BFS는 큐에 무한 삽입.

```py
# 정점이 숫자
graph = [[] for _ in range(N + 1)]
# 정점이 알파벳 (8~13번)
graph = {v: [] for v in vertices}
for _ in range(M):
    u, v = input().split()
    graph[u].append(v)
    graph[v].append(u)     # 양방향이면 양쪽!
for v in vertices:
    graph[v].sort()        # 알파벳 순 방문 조건
```

> ❌ 실제 틀린 것(15제 12번): `nodes`만 정렬하고 `g[i]` 이웃을 정렬 안 함 → 사전순 최소 경로가 아님. "알파벳 순서/사전순"이 보이면 **각 정점의 이웃 리스트**를 정렬했는지 확인.

# 5️⃣ 🔥 Dijkstra (약 30점)

## 왜 BFS로 안 되나

BFS는 **간선 개수**를 최소화. 간선마다 비용이 다르면 "적게 거친 길" ≠ "적게 드는 길".

| 간선 비용 | BFS로 최소비용? | Dijkstra? |
|-----------|-----------------|-----------|
| 모두 같고 0 이상 | ⭕ | ⭕ |
| 서로 다르지만 0 이상 | ❌ | ⭕ |
| 음수 포함 | ❌ | ❌ |

## 저장 구조 (헷갈리기 1순위)

| 이름 | 형태 | 의미 |
|------|------|------|
| `graph[u]` | `(이웃, 간선 비용)` | 간선 하나의 비용 |
| `pq` | `(누적 비용, 정점)` | **비용이 앞**이어야 힙이 비용 작은 것부터 |
| `dist[v]` | 숫자 (출발 0, 나머지 ∞) | 현재까지 발견한 최소 비용 |

## ⭐ 통째로 외울 기본 코드

```py
import heapq

N, M = map(int, input().split())
S, T = map(int, input().split())

graph = [[] for _ in range(N + 1)]
for _ in range(M):
    u, v, w = map(int, input().split())
    graph[u].append((v, w))
    graph[v].append((u, w))   # 무방향일 때만! 방향이면 삭제

def dijkstra(start):
    INF = float('inf')
    dist = [INF] * (N + 1)
    dist[start] = 0
    pq = [(0, start)]                 # (누적 비용, 정점)
    while pq:
        d, cur = heapq.heappop(pq)    # ① 누적 비용 최소 꺼내기
        if d > dist[cur]:             # ② 오래된 후보 버림
            continue
        for nxt, w in graph[cur]:
            nd = d + w                # ③ 누적 + 간선
            if nd < dist[nxt]:        # ④ 더 좋으면
                dist[nxt] = nd        #    갱신 (Relaxation)
                heapq.heappush(pq, (nd, nxt))   # ⑤ 후보 추가
    return dist

dist = dijkstra(S)
print(dist[T] if dist[T] != float('inf') else -1)
```

## 두 조건문의 역할

|  | `nd < dist[nxt]` | `d > dist[cur]` |
|--|------------------|-----------------|
| 질문 | 새 경로가 더 좋은가? | 꺼낸 후보가 오래됐나? |
| 위치 | 간선 따라갈 때 | 힙에서 꺼낸 직후 |
| 결정 | 기록 바꾸고 후보 추가 | 이 후보 버림 |

## 예상 서술 핵심

- **우선순위 큐 왜?**: 처리 안 한 후보 중 누적 비용 최소부터 처리해야 최단 보장. 매번 전체 훑으면 느려서 최소 힙(O(log k)).
- **왜 꺼낸 최소를 확정?**: 남은 후보는 이미 비용이 그 이상. 모든 간선 ≥ 0이면 비용은 줄지 않음 → 더 작은 경로 없음.
- **오래된 후보**: 힙은 중간 삭제가 안 돼 예전 후보가 남음 → `if d > dist[cur]: continue`로 버림. 없어도 출력은 같지만 효율 나빠짐.
- **넣을 때 visited 표시하면?**: 처음 값으로 고정 → 나중에 더 짧은 경로 못 반영 → 오답.
- **왜 힙 빌 때까지?**: 모든 정점 출력 문제는 끝까지. 단일 목표(14번)는 목표가 **pop될 때** 확정이라 그때 break 가능.
- **`<=`로 쓰면?**: 같은 비용 후보 중복 추가, 비용 0 사이클이면 무한 반복.
- **음수 간선?**: 그리디 전제 깨짐 → Bellman-Ford.
- **시간 복잡도**: O((N + M) log M).

## 응용 (15제 15번: 경유지 K)

```py
from_s = dijkstra(S)
from_k = dijkstra(K)
INF = float('inf')
if from_s[K] == INF or from_k[T] == INF:
    print(-1)
else:
    print(from_s[K] + from_k[T])
```

## 자주 하는 실수

| 실수 | 현상 | 고치는 법 |
|------|------|-----------|
| 방향인데 역방향도 추가 | 없는 경로로 작은 값 | `graph[u]`에만 |
| `(정점, 비용)` 순서 | 번호 작은 것부터 → 오답 | `(비용, 정점)` |
| `nd = w` (누적 안 함) | 간선 하나만 비교 | `d + w` |
| 넣을 때 visited | 처음 값 고정 → 오답 | 꺼낼 때 비교 |
| 갱신 `<=` | 중복 추가 | `<` |
| 발견하면 break | 최종값 아님 | 힙 빌 때까지 (단일 목표면 pop 시점) |
| INF 그대로 출력 | `inf` 출력 | −1로 변환 |
